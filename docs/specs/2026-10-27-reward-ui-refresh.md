## 1. 背景・目的

添付のUI改善案をもとに、対応済みのTodo画面と同じMaterial配色・標準フォントでごほうび一覧・詳細を刷新する。チケット残数、ガチャ操作、各ごほうびの当選確率を読み取りやすくする。

## 2. 要件

### 機能要件

- 一覧上部に所持チケット、単発・10連ガチャをまとめた角丸パネルを配置する。両ボタンの幅と高さを揃える。
- ごほうび一覧の見出しに追加ボタンを置き、各項目をレア度付きの角丸カードで表示する。
- カードには名前、当選確率、レア度、リピート／1回限りを表示する。説明は詳細で表示・編集する。
- 詳細に名前、任意の説明、確率の数値入力とスライダー、当選後もプールに残すスイッチ、保存・削除を配置する。新規追加時は削除を表示しない。
- スライダーは0〜100%。数値入力で細かな確率を設定でき、レア度表示も連動する。
- 日本語の画面表記はユーザー指定の「ごほうび」「ガチャ」に統一する。「排出ラインナップ」は「ごほうび一覧」、「リピート報酬」は「リピート」とする。当選確率・当選／はずれは確率・結果の用語として使う。
- Todo・Reward両タブのステータスバーを上部バーと同じオレンジにする。時計・アイコンは起動時に暗色へ設定し、画面遷移による動的制御は追加しない。

### 非機能要件 / 制約

- ライト／ダークに対応する。詳細を縦スクロール可能にし、キーボード表示中も操作できるようにする。
- 追加上限7件、リピートの既定値、保存・削除、ガチャ・チケット消費、二重実行防止、プル更新、エラー通知を維持する。
- 結果ダイアログ・振動は既存の動作を維持する。資料のガチャ結果アニメーションは対象外。
- 保存済みデータや通信契約、新規依存を変更しない。
- リピートの読み上げは翻訳済みのテキストに集約し、装飾アイコンに英語の説明を付けない。
- E2Eの残数検証は`ticket_count`の残数表示と実値を照合する。ガチャボタンの消費枚数を残数として検証しない。

## 3. 画面・UX

- 対象画面: `RewardListScreen`、`RewardListContent`、`RewardItem`、`RewardDetailBottomSheet`、ホーム画面のステータスバー。
- UI変更点: チケット・ガチャパネル、レア度カード、編集フォーム、確率スライダー、リピートスイッチ。リスト全体をスクロールでき、操作ボタンと項目が重ならない。
- 操作フロー: 一覧から追加またはカードを選択 → 詳細で編集 → 保存成功後に閉じる。既存項目は削除も可能。所持チケットを使って単発／10連ガチャを実行し、結果ダイアログを閉じると更新された残数を確認できる。
- レア度は表示上の分類とする。0.2%以下はLEGEND、0.5%以下はEPIC、1%以下はRARE、それ以上はNORMAL。
- 一覧・状態別Previewにもアプリテーマを適用し、実画面と異なるMaterial標準の紫で撮影しない。

## 4. ドメインへの影響

[ドメインモデル](../domain-model.md)に定義された`Reward`、`RewardId`、`RewardName`、`RewardDescription`、`Probability`、`RewardCollection`、チケット残数を既存のViewModel／UseCase経由で扱う。

- 新規追加・変更するビジネスルールはない。レア度は表示上の分類であり、当選確率の計算を変更しない。
- Domain／Application／Data／DI、DBスキーマ、保存済みデータの変換・削除は変更しない。

## 5. レイヤー別の変更方針

[モジュール依存関係](../module-dependency.md)の依存ルールを維持する。

| レイヤー | モジュール | 変更内容 |
|---------|-----------|---------|
| Feature | `feature:reward` | 一覧・詳細、レア度表示、Previewのテーマ、日本語文言、読み上げ、残数表示のテスト用識別子 |
| App | `app` | ステータスバーの背景・起動時アイコン色 |
| Test | `feature:reward` / `maestro-tests` | 境界値・編集・残数・読み上げの検証、既存E2Eの要素指定と保存完了待ち |

## 6. 受け入れ条件 (Acceptance Criteria)

- [x] ライト／ダークでカードの名前、確率、レア度、リピート状態を読める。
- [x] 単発・10連ボタンの大きさが揃い、実行中の重複操作を防止する。
- [x] 一覧から追加・編集・削除でき、保存成功後に詳細が閉じる。
- [x] 確率を数値入力・スライダーで設定でき、レア度が定義した境界値に従う。
- [x] リピート項目は当選後も残り、1回限りの項目は当選後に削除される。
- [x] ガチャ成功・チケット不足の通知と残数更新が機能する。
- [x] ホームのステータスバーがオレンジになり、両テーマで時計・アイコンを読める。
- [x] 日本語表記が「ごほうび」「ガチャ」で統一され、リピート状態の読み上げが重複しない。
- [x] E2Eが消費枚数のラベルではなく、所持チケットの実値を検証する。

## 7. テスト方針

| 種別 | 対象 |
|------|------|
| ユニットテスト | レア度の境界値、詳細保存時のID・確率・リピート、新規追加時の既定値、削除対象、リピートのテキスト、残数と消費枚数の区別。既存ViewModelテストも実行 |
| Roborazzi | ライト／ダークの一覧・詳細と状態別Previewを描画し、テーマとレイアウトを確認 |
| Maestro E2E | 既存の追加・編集・削除、単発・10連成功、チケット不足、リピート維持・単発削除、Todo完了後の残数を検証 |

### これまでの確認結果

- 全単体テスト173件、Debug／E2Eビルド、Spotless、独自detektが成功。報酬モジュールlintは既存警告1件、App lintは問題なし。
- 一覧・詳細のライト／ダーク画像を確認し、Pixel 8aへインストールして動作確認した。
- 追加・編集・削除・単発・10連成功／不足のE2Eを確認。CIで失敗した2フローの余分な`hideKeyboard`を削除し、リピート維持・単発削除も手元で成功。
- ステータスバーをエミュレータのライト／ダークで確認し、認証からホームへの遷移・再起動のE2Eも成功。
- CodeRabbit指摘後、関連E2E7件が成功。残数0枚を1枚のコスト表示と誤認しないこと、10連で12枚から2枚へ減ること、翻訳済みリピート表示を確認。日本語の実画面でも「ごほうび一覧」「ガチャを引く」「10連ガチャ」と詳細の文言を確認。

## 8. 未決事項・リスク

- 小画面・文字サイズ拡大・通信失敗時の実機操作は網羅していない。
- ガチャ結果のアニメーション演出は今回の対象外。
